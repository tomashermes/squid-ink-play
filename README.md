# Squid Ink — Google Play wrapper

Android (Capacitor 8) wrapper for **[squid-ink](https://github.com/tomashermes/squid-ink)**,
prepared for Google Play + AdMob. **iOS deliberately skipped for now.**

The game is unchanged: `www/index.html` is the same single-file build plus
exactly one wrapper-only diff — three `<script>` tags before `</body>` loading
`audio-theme.js` + `AdsBridge.js` + `ads-integration.js` (regenerated by
`npm run sync-web`, so the game repo stays the single source of truth).
The only intentional *behavioural* difference vs the browser game: the Play
build uses the **bubbles-and-sea ambience** instead of the song (selected by
`audio-theme.js` through the game's documented theme seam); the squishy
water-blob flap sound is the same everywhere.

## Layout

```
www/                    webDir for Capacitor
  index.html            game copy + 3 injected script tags (see sync-web)
  audio-theme.js        sets window.SQUID_INK_AMBIENCE="ocean" (bubbles & sea
                        ambience instead of the song; squish flaps unchanged)
  AdsBridge.js          screen-state seam (no-op off-device)
  ads-integration.js    MutationObserver → banner on START & GAME-OVER only
                        (Google DEMO test banner; TESTING flag + REPLACE_ME slot)
android/                generated Capacitor project, committed; manifest has
                        AdMob APPLICATION_ID meta-data (demo test id — swap!)
PUBLISH.md              step-by-step: AdMob console, Play Console, policy check
capacitor.config.json   appId com.tomashermes.squidink (PERMANENT after first upload)
```

## Build (this machine)

Toolchain lives in `/hermes/outputs/tools/` (JDK 17 + Android cmdline-tools):

```bash
export JAVA_HOME=/hermes/outputs/tools/jdk17
export ANDROID_HOME=/hermes/outputs/tools/android-sdk
export PATH="$JAVA_HOME/bin:/home/tomas/.hermes/tools/node-26.12.1-linux-x64/bin:$PATH"
sdkmanager --licenses >/dev/null <<< y   # first time
sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"  # first time
npm install && npx cap sync android
npm run build        # debug APK → android/app/build/outputs/apk/debug/
```

No Android device plugged in? The debug APK still installs on any phone via
Files-by-URL or `adb install`; demo test banners render without an AdMob
account (they're Google's public demo units).

## Ad policy encoded here (do not "improve" without re-reading PUBLISH.md)

- One bottom anchored-adaptive **banner**, only on start & game-over screens;
  never during flying/paused (tap-anywhere controls → mis-click policy).
- No interstitials, no rewarded revive (contradicts the game's published
  no-pressure design law).
- Development builds use **Google's official demo unit IDs**
  (`ca-app-pub-3940256099942544/…`, verified 15.11.2026 from
  developers.google.com). Production IDs go in **two** places only:
  `android/.../AndroidManifest.xml` (app id) and `www/ads-integration.js`
  (banner unit + `TESTING=false`). Never commit them; never invent them.
- ATT/iOS: N/A (Android-only). Tracking default: none beyond what the Mobile
  Ads SDK does itself.

## Update flow

`npm run sync-web` re-copies the game from `../squid-ink`, re-injects the
three script tags, and re-syncs Android assets.
